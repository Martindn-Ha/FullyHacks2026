Hackathon Diabetes Support AppHuman Delta Integration & Implementation BriefWorkflow, system architecture, and Cursor-ready build guidanceCore concept: the app predicts a glucose spike, uses Google Maps to find nearby food options, uses Human Delta to retrieve indexed menu and nutrition guidance, and then recommends healthier choices. The app—not Human Delta—owns prediction, ranking, guardrails, and escalation.1. Executive SummaryHuman Delta is best used here as a knowledge retrieval layer, not as the core intelligence of the project. In this hackathon version, the diabetes app remains responsible for collecting user inputs, estimating glucose-spike risk, applying safety logic, and generating the final recommendation. Human Delta contributes by indexing restaurant pages, menus, nutrition content, and curated food-guidance documents so the app can retrieve grounded information before recommending a nearby meal option.Recommended positioning for judges: “Our app predicts when a glucose spike may occur, uses Google Maps to find nearby food options, and uses Human Delta to retrieve menu knowledge so we can recommend better choices in real time.”2. What Human Delta Does in This Project* Indexes restaurant menu pages, nutrition pages, uploaded menu PDFs, and curated food-guidance notes.* Provides one searchable corpus that the backend can query at recommendation time.* Returns grounded menu or guidance passages that the app can use for explanation and ranking.* Does not replace the app’s prediction model, safety logic, or recommendation-ranking rules.Simple division of responsibility: Google Maps answers “what places are nearby?” Human Delta answers “what do those places serve, and which items look better for this context?” The app answers “which option should we present to the user right now?”3. User Workflow1. Collect user context: The mobile app gathers glucose trends, meals, symptoms, medication status, activity, and location.2. Estimate risk: A backend risk engine predicts the likelihood of a near-term glucose spike and classifies severity.3. Find nearby options: If risk is elevated, the backend queries Google Maps Places API for nearby restaurants, cafes, or grocery options.4. Retrieve menu knowledge: The backend queries Human Delta for indexed menu, nutrition, and guidance content associated with those nearby locations.5. Apply ranking and guardrails: The recommendation engine scores options based on risk level, distance, and retrieved guidance, while hardcoded safety rules suppress unsafe advice or escalate when needed.6. Show the recommendation: The app displays the top healthier nearby options, a suggested meal item, and a short plain-language explanation.4. System DiagramFigure 1. Technical ArchitectureComponentRoleMobile app (Expo / React Native)Collects user input, sends the request, and displays recommendations and warnings.Backend API (Node.js + Express or Python + FastAPI)Orchestrates calls to the risk engine, Google Maps, Human Delta, and the recommendation logic.Risk engineCalculates spike-risk score and severity label from user context. Can start as a rules-based or mock model for the hackathon.Google Maps Places APIFinds nearby restaurants or grocery options.Human DeltaStores indexed menu pages, nutrition docs, and curated restaurant guidance and returns relevant passages.Recommendation engineRanks candidate options using risk, distance, and retrieved content.Safety / rules layerOverrides risky recommendations and handles urgent symptom escalation with deterministic logic.Recommended project structure: /services/riskEngine, /services/googleMapsClient, /services/humanDeltaClient, /services/recommendationEngine, and /services/safetyRules. Keep Human Delta behind a service boundary so it remains a dependency, not the center of the app.6. Data and Retrieval ScopeFor the hackathon, keep the indexed corpus narrow and demo-friendly. A strong MVP would index menu and nutrition content for a handful of recognizable chains or a small set of local restaurants near the demo area.* Official restaurant menu pages* Nutrition pages for common chains* Uploaded menu PDFs* Curated markdown notes summarizing healthier picks and caution items* Optional diabetes-friendly meal guidance documents used only for explanation, not diagnosisBest MVP pattern: Google Maps finds places, the backend filters to restaurants you have indexed, Human Delta retrieves menu guidance for those candidates, and the recommendation engine ranks the top three options.7. Implementation PlanPhase 1 — Scaffold* Create the Expo frontend and backend API structure.* Add environment variable placeholders for Google Maps and Human Delta keys.* Implement a mock spike-risk engine first so the app works before model training is complete.Phase 2 — Core services* Implement POST /api/risk-assessment.* Implement POST /api/nearby-restaurants using Google Maps Places API.* Implement a Human Delta client and POST /api/menu-guidance.Phase 3 — Recommendation orchestration* Implement POST /api/recommendations to run the full flow: assess risk, fetch nearby places, retrieve menu guidance, rank options, and return the top recommendations.* Add deterministic safety rules that override food recommendations when urgent symptoms are present.Phase 4 — UI and demo polish* Build a recommendation screen showing the risk level, top three nearby food options, a suggested item, and a short explanation.* Optionally show a small “grounded by indexed menu guidance” note to make the Human Delta integration visible to judges.8. Safety and Product Constraints* Do not present food suggestions as medical diagnosis or guaranteed treatment advice.* Use hardcoded escalation rules for urgent symptoms such as fainting, confusion, severe dizziness, or similar danger signals.* Use Human Delta for menu and guidance retrieval, not as the sole decision-maker for medical risk.* Keep recommendation language supportive and practical: “healthier option,” “better fit for high spike risk,” or “lower-sugar/lower-carb alternative.”9. Judge-Facing Pitch Language* “Our app predicts when a glucose spike may occur, uses Google Maps to find nearby food options, and uses Human Delta to retrieve menu knowledge so we can recommend better choices in real time.”* “Human Delta powers the knowledge layer behind our food recommendations, while our app handles prediction, safety logic, and ranking.”11. Final RecommendationFor this hackathon, the strongest use of Human Delta is not as a broad medical advice engine. It is as a visible, practical retrieval layer that helps the app explain and justify healthier nearby food recommendations after a predicted glucose spike. That use is easy to demo, easy to explain, sponsor-friendly, and naturally connected to the core value of the project.Hackathon Diabetes App — Human Delta Integration BriefPage 1
